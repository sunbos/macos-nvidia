# 重装与恢复准备

状态：材料与流程归档。尚未在空白 macOS 安装上完成本组合的重建和恢复演练，不应照抄历史事务脚本直接写系统。

## 重装前必须保留

1. 匹配版本的 macOS 安装/恢复介质与可用的核显启动方案。先实际验证能进入恢复环境；“存在 Recovery 分区”不等于恢复路径已经验证。
2. 全部磁盘数据备份和完整 EFI 离线副本，包括 Windows `EFI/Microsoft`；保留本机 SMBIOS，但不把它提交到公开仓库。
3. 此 profile 的固定 Git commit、组件清单和本地源码补丁。另存当前可用 NVIDIA 完整 bundles、四个 kext、NVK/运行库、固件、allowlist、配置及逐文件摘要，保留 symlink 语义。仅保存几个 dylib 不够。
4. OCLP-Mod 3.1.9、对应 PatcherSupportPkg 来源/摘要、`KDK_26.7.1_25G241.kdk` 的合法获取方式。精确安装材料须核对，不能仅以应用版本号代替 payload 内容。
5. 与当前 OS build 匹配的内核集合和 OCLP receipt 的私有诊断副本。它们有助于分析回退，不能当作跨系统版本可直接恢复的通用文件。

以上材料应再复制到独立磁盘。聊天记录、GitHub 源码或同一块待格式化磁盘上的备份都不是完整灾难恢复。

## 建议重装顺序（待空白安装演练）

1. 使用保留的核显方案启动匹配 build 的 macOS，先确认内屏、磁盘与输入设备。
2. 按已验证 OCLP-Mod 路线完成无线/音频根补丁、匹配 KDK、Boot/System 内核集合重建；由用户重启，再确认输出设备及 Wi-Fi。
3. 根据该新系统的实际状态，构建可回滚的 NVIDIA 安装事务。逐项核对 headless、Intel 内屏、ACPI dGPU 电源和 OCLP 共存要求。不要照搬其它机型或旧 boot 的事务 plan。
4. 安装前验证新备份和恢复入口，再做组件文件、架构、签名/权限、内核集合依赖检查。由用户决定何时重启。
5. 新启动后先验证加载的 kext UUID/组件 hash，再显式选择 NVIDIA 做 CPU oracle 对照的 Metal 复制、计算、离屏渲染。设备名称出现不算完成。
6. 再分别验收应用、视频编解码、性能、睡眠/唤醒和长时间运行。每份结果记录实际 GPU 身份与分数，禁止把 Intel 结果记作 NVIDIA。

本次 OCLP 根补丁曾移动 NVIDIA framebuffer/AGDC kext，说明两个安装流程可能相互影响。重新运行 OCLP 后必须再次核对 NVIDIA 文件、内核集合及新启动结果。

## 恢复边界

- 原 Yoga 仓库保留为核显 EFI 基线；替换 EFI 不会自动卸载 `/Library` 中的 NVIDIA 组件或恢复 APFS 内核集合。
- 历史回滚脚本保存的是特定时刻的 bundle、AuxKC 和保护文件。用户后来重新做过 OCLP 根补丁，不可未经比较就恢复旧 AuxKC，否则可能丢失当前音频/无线集成。
- 若最新版安装后异常，先保存其日志和实际文件摘要，再选择针对本次安装的回滚或核显恢复。不能靠修改 GPU 名称、静默切回 Intel 来宣称修复。
- v2.3.1 自带失败回退可能自动重启。评估安装前必须了解这一行为；本仓库归档流程不运行它，也不启动重启。

## 成为可重装发行包前的剩余工作

统一构建依赖和可移植路径；固定完整预编译输入/固件的获取与校验；开发基于新系统状态的安装和卸载/回退入口；在备用 APFS 卷或独立磁盘完成一次从核显启动到 NVIDIA 实测再回退的演练。未完成这些步骤前，源码归档不标注为可一键恢复的稳定 Release。
